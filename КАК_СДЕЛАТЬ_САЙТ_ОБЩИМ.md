# Как сделать сайт общим (мгновенные обновления) и разместить на GitHub

Теперь сайт работает так:

- **Хостинг сайта** — GitHub Pages (бесплатно, прямо из вашего репозитория).
- **Общая база данных** — Supabase (бесплатно, PostgreSQL + мгновенный
  realtime). Дашборд и сам сайт работают из России без VPN — карта
  нужна только для платных тарифов, а бесплатный тариф её не требует.

Режимы работы:

- **Без настройки Supabase (по умолчанию)** — каждый посетитель видит
  свою копию данных в своём браузере. Ничего не сломано.
- **С настроенным Supabase** — каталог, заказы, клиенты и чат
  поддержки общие для всех, а изменения (например, новый заказ или
  правка в админке) появляются у всех открытых вкладок **мгновенно**,
  без перезагрузки и без задержек — это и есть realtime.

## Часть 1. Общая база данных (Supabase)

### Шаг 1. Создайте проект Supabase

1. Зайдите на **https://supabase.com** → «Start your project» →
   войдите через GitHub (проще всего) или почту.
2. Нажмите **New project**, впишите любое имя (например,
   `lakomiy-kusochek`), придумайте пароль от базы (сохраните его —
   пригодится, если понадобится прямой доступ к базе) и выберите
   ближайший регион (например, Frankfurt).
3. Дождитесь, пока проект создастся (около минуты).

### Шаг 2. Создайте таблицы и включите realtime

1. В боковом меню проекта откройте **SQL Editor** → **New query**.
2. Откройте файл `supabase-schema.sql` из этого проекта, скопируйте
   **весь** его текст и вставьте в редактор.
3. Нажмите **Run**. Должно появиться сообщение об успехе — это
   создаст 5 таблиц (`cakes`, `users`, `orders`, `settings`,
   `support_chats`) и включит для них мгновенные обновления.

### Шаг 3. Впишите ключи подключения в сайт

1. В боковом меню откройте **Project Settings** (шестерёнка) → **API**.
2. Скопируйте:
   - **Project URL** (выглядит как `https://xxxxx.supabase.co`);
   - ключ **anon public** (длинная строка).
3. Откройте файл `js/backend-config.js` в этом проекте и впишите:
   - `SUPABASE_URL` — вставьте Project URL;
   - `SUPABASE_ANON_KEY` — вставьте ключ anon public.
4. Сохраните файл.

С этого момента при открытии сайта он сам увидит, что база пустая, и
один раз заполнит её тестовыми тортами/заказами — дальше все
изменения будут общими и мгновенными для всех посетителей.

### Если таблицы в Supabase уже были созданы раньше

Пароли пользователей теперь хранятся не открытым текстом, а в виде
хеша (нечитаемого «отпечатка»). Если вы уже выполняли
`supabase-schema.sql` раньше (до этого обновления), дополнительно
выполните через **SQL Editor** ещё и файл
`supabase-migration-salt.sql` — он добавит недостающее поле `salt`
для существующей таблицы `users`. Если создаёте базу впервые —
этот файл не нужен, всё уже учтено в `supabase-schema.sql`.

Старые аккаунты (с паролем, сохранённым ещё открытым текстом) ничего
специально мигрировать не нужно — как только такой пользователь один
раз успешно войдёт, сайт сам незаметно перезапишет его пароль в виде
хеша.

## Часть 2. Разместите сайт на GitHub Pages

### Шаг 1. Загрузите проект в репозиторий на GitHub

1. Зайдите на **https://github.com** → войдите или зарегистрируйтесь.
2. Нажмите **New repository**, дайте имя (например,
   `lakomiy-kusochek`), оставьте «Public», нажмите **Create repository**.
3. Загрузите все файлы этого проекта в репозиторий — проще всего
   через кнопку **«uploading an existing file»** на странице
   репозитория (перетащите туда всю папку целиком) и нажмите
   **Commit changes**.

   (Если привычнее через командную строку — `git init`, `git add .`,
   `git commit -m "первый коммит"`, `git remote add origin <адрес
   репозитория>`, `git push -u origin main`.)

### Шаг 2. Включите GitHub Pages

1. В репозитории откройте **Settings** → **Pages** (в боковом меню).
2. В разделе **Build and deployment** → **Source** выберите
   **Deploy from a branch**.
3. В **Branch** выберите `main` и папку `/ (root)` → **Save**.
4. Через минуту-две вверху появится ссылка вида
   `https://ваш-логин.github.io/lakomiy-kusochek/` — это и есть
   готовый сайт.

### Готово

Ссылку можно отправлять друзьям или клиентам. После любых правок в
файлах достаточно снова закоммитить изменения в репозиторий (или
перезалить изменённые файлы) — GitHub Pages сам обновит сайт в
течение минуты, никаких дополнительных действий не нужно.

## Важно про безопасность

Это упрощённая защита — подходит для сайта-визитки/демонстрации:

- Пароли пользователей (в т. ч. администратора сайта) хранятся
  открытым текстом — **не используйте реальные пароли**, которые вы
  применяете где-то ещё.
- Доступ к базе открыт на чтение и запись всем, у кого есть ссылка на
  сайт (через публичный «anon»-ключ) — это удобно для демо, но не
  полноценная защита с личным кабинетом на сервере.
- Если сайт вырастет в настоящий бизнес с реальными платежами и
  личными данными клиентов — потребуется более серьёзная защита
  (например, Supabase Auth + RLS-политики по пользователю).
  Обращайтесь, когда до этого дойдёт.

## Если что-то не работает

Откройте сайт, нажмите F12 (консоль разработчика) → вкладка Console.

- Если там ошибка про Supabase — проверьте, что `SUPABASE_URL` и
  `SUPABASE_ANON_KEY` в `js/backend-config.js` скопированы без
  пробелов и опечаток.
- Если в консоли пишет «Realtime подключён» (или похожее), а
  обновления всё равно не мгновенные — проверьте в Supabase, что в
  SQL Editor файл `supabase-schema.sql` выполнился без ошибок целиком
  (особенно последний блок с `alter publication supabase_realtime`).
- Если сайт на GitHub Pages не открывается — проверьте в Settings →
  Pages, что статус «Your site is live at …», и что в репозитории
  файл `index.html` лежит прямо в корне (не во вложенной папке).

Пришлите текст ошибки — разберёмся.
