# Как разместить сайт на российском хостинге и сделать данные общими

Сайт больше не зависит от зарубежных сервисов (раньше — Netlify для
размещения и Supabase для общей базы данных, плюс Google Fonts и CDN
unpkg.com). Теперь всё можно разместить на одном российском хостинге:

- **HTML/CSS/JS сайта** — обычные статические файлы.
- **Общая база данных** — свой маленький бэкенд на PHP + MySQL
  (папка `backend/`), работающий прямо на том же хостинге.

Режимы работы остались те же:

- **Без настройки бэкенда (по умолчанию)** — каждый посетитель видит
  свою копию данных в своём браузере. Ничего не сломано.
- **С настроенным бэкендом** — каталог, заказы, клиенты и контакты
  общие для всех, изменения в админке видны всем посетителям (сайт
  сам обновляет данные каждые несколько секунд).

## Шаг 1. Закажите бесплатный хостинг с PHP и MySQL

Подойдёт российский хостинг с поддержкой PHP и MySQL. Например,
**SpaceWeb (sweb.ru)** — бесплатный тариф включает PHP, MySQL,
SSL-сертификат и тестовый домен вида `ваш-сайт.swtest.ru`:

1. Зайдите на **https://sweb.ru/hosting/free/** → закажите бесплатный тариф.
2. Зарегистрируйтесь, подтвердите номер телефона/почту.
3. В панели управления хостингом создайте базу данных MySQL —
   запишите её имя, пользователя и пароль (понадобятся на шаге 3).

(Похожие бесплатные тарифы с PHP+MySQL есть и у других российских
провайдеров — 2domains, GlavHost и т. п.; шаги ниже подойдут для
любого хостинга с phpMyAdmin.)

## Шаг 2. Загрузите файлы сайта на хостинг

В панели управления хостингом откройте **Файловый менеджер** (или
подключитесь по FTP — данные для этого тоже есть в панели) и
загрузите **всё содержимое** папки `lakomiy-kusochek` в корень сайта,
сохранив структуру папок как есть (включая `backend/`).

## Шаг 3. Создайте таблицы в базе данных

1. В панели хостинга откройте **phpMyAdmin** для созданной на шаге 1 базы.
2. Откройте вкладку **«Импорт»**, выберите файл `backend/db-schema.sql`
   из проекта и нажмите **«Ок» / «Импортировать»**.
3. Должны появиться 4 таблицы: `cakes`, `users`, `orders`, `settings`.

## Шаг 4. Впишите настройки подключения

1. Откройте файл `backend/db-config.php` (через файловый менеджер
   хостинга или заранее в редакторе перед загрузкой) и впишите:
   - `DB_NAME`, `DB_USER`, `DB_PASSWORD` — данные базы из шага 1
     (`DB_HOST` обычно остаётся `localhost`);
   - `API_KEY` — придумайте любой пароль (просто набор символов).
2. Откройте файл `js/backend-config.js` и впишите:
   - `BACKEND_URL` — адрес папки `backend` на вашем сайте, например
     `https://ваш-сайт.swtest.ru/backend`;
   - `BACKEND_KEY` — **тот же** пароль, что вписали в `API_KEY` выше.
3. Сохраните оба файла (и перезалейте их на хостинг, если правили
   заранее локально).

С этого момента при открытии сайта он сам увидит, что база пустая, и
один раз заполнит её тестовыми тортами/заказами — дальше все
изменения в админке будут общими для всех посетителей.

## Готово

Ссылку на сайт (например, `https://ваш-сайт.swtest.ru`) можно
отправлять друзьям или клиентам. После правок в этом чате достаточно
перезалить изменённые файлы в файловый менеджер хостинга.

## Важно про безопасность

Как и раньше в демо-варианте с Supabase, это упрощённая защита:

- Пароли пользователей (в т. ч. администратора сайта) хранятся
  открытым текстом — **не используйте реальные пароли**, которые вы
  применяете где-то ещё.
- Доступ к бэкенду защищён общим «паролем» (`API_KEY`/`BACKEND_KEY`),
  а не полноценной системой прав доступа.
- Если сайт вырастет в настоящий бизнес с реальными платежами и
  личными данными клиентов — потребуется более серьёзная защита.
  Обращайтесь, когда до этого дойдёт.

## Если что-то не работает

Откройте сайт, нажмите F12 (консоль разработчика) → вкладка Console.
Если там ошибка про бэкенд/API — скорее всего:

- не совпадает `API_KEY` и `BACKEND_KEY`;
- неверно указан `BACKEND_URL` (проверьте, что по этому адресу в
  браузере открывается `api.php`, например
  `https://ваш-сайт.swtest.ru/backend/api.php?table=cakes` — должен
  вернуться пустой список `[]`, а не ошибка 404);
- не импортирована `backend/db-schema.sql` или неверные данные в
  `db-config.php`.

Пришлите текст ошибки — разберёмся.
